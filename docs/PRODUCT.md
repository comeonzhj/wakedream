# WakeDream 产品定义

> 归属：lead。回答「这是什么、给谁、做什么、不做什么」。

## 平台与形态
Node.js ≥ 22.5 常驻进程 + 浏览器 UI（`http://127.0.0.1:4680`），数据全在本机 `~/.wakedream`。零运行时依赖、无打包步骤；同一份代码在两台设备上跑即可互为局域网对端。

## 用户与场景
同时用多个 coding agent、且会话散落在多台设备上的个人用户。典型场景：晚上（或次日早上）想知道「今天我和这几个 agent 到底干了什么、决定了什么、还有什么没定」，以及「明天开新会话时，能不能让 agent 一开始就知道这些」。

## 三个动作与成功标准
| 动作 | 功能 | 成功标准 |
|---|---|---|
| 收 | 扫描本机各 agent 会话；SSH 镜像远机会话；局域网拉取同网设备会话 | 当天会话在一处可浏览、可搜索，远端会话带 `@host` 身份；索引可随时重建 |
| 梦 | 夜间把当天会话萃取成 wiki 式记忆库（`_index.md` + 小文件），每条结论可回溯到来源会话 | 跑完 5 分钟内人能读懂「今天干了什么、决定什么、还差什么」；重跑幂等；无 key 时也能出可用结果 |
| 用 | 浏览/检索/阅读转录；查看历次梦报告；把记忆库目录以只读方式挂给新会话 | 从「想找某次会话」到打开它不超过几步；记忆挂载指令可一键复制 |

## 信息架构（对应用户心里的三个问题）
1. **今天发生了什么？** → 今日页：时间线 + 统计 + 做梦状态。
2. **那件事是在哪聊的？** → 会话页 + 转录页：分组、筛选、全文子串搜索、工具调用折叠、`@host` 徽章。
3. **那我该怎么记住它？** → 梦页 + 记忆页：报告、记忆文件树、可复制的挂载指令；设备页管理这些会话从哪来。

## 与 Wake 的关系（复用与差异）
- 复用：会话为唯一事实源、只读别家数据、索引可重建、agent 品牌色识别、`@host` 远程徽章、Remote hosts 的 SSH 白名单镜像思路、三栏阅读体验。
- 差异：Wake 是「找回一段对话」（检索与恢复，只读记忆层）；WakeDream 是「把一天的对话变成记忆」（夜间批量萃取 + 只读挂载 + 跨设备收拢）。Wake 不做摘要层也不写记忆是它的克制；WakeDream 把这件事做成主功能，因此必须自带 provider 开关、成本可见、结论可回溯、可重跑。

## 关键设计决定
- **夜间批处理而非实时**：萃取需要「事后 hindsight」（哪些当时以为对、其实错了；什么才值得记），批量也天然有预算上限与幂等重跑。
- **wiki 式小文件而非向量库**：可读、可 diff、可手工修正、可被任意 agent 用普通文件工具读取；不引入 embedding 依赖。
- **只读挂载而非自动写入别家记忆**：不破「不写别家数据」的铁律，用户自己决定把哪份记忆挂给谁。
- **结论必须带 `source_sessions`**：记忆可以被质疑、被回溯，这是它敢被下个会话信任的前提。
- **provider 可降级**：默认本地启发式（不发数据出去），要用模型时由用户显式开启并看到成本。

## 不做
云端账号与多端托管、向量库/知识图谱、自动改别家配置、远端写操作、会话内容上传到任何非用户配置的端点。
